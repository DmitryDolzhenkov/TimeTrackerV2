# TimeTracker — PRD

Исходная постановка: [problem.md](problem.md). Термины: [GLOSSARY.md](../GLOSSARY.md). Решения: [docs/adr/](adr/).

Принцип: production-minded, but intentionally simple.

## 1. Проблема

Сейчас рабочее время учитывается вручную и на глаз. Нужен простой таймер для Windows, который запускается одной кнопкой, сам перестаёт считать время, когда пользователь отсутствует, и показывает историю своих состояний.

## 2. Scope

### Входит

- Один Timer без проектов, задач и категорий.
- Пять Timer State: Stop, Active, Idle, Lock, Shutdown.
- Автоматическое определение неактивности, блокировки и выключения компьютера.
- Показ длительности текущей Daily Session.
- Ручные Adjustment текущей Daily Session.
- Просмотр Timer Log.

### Не входит

- Реализация для Linux и macOS. Доменная модель при этом не зависит от платформы.
- Отчёты, экспорт и сбор данных по пользователям сети.
- Сервер и синхронизация.
- Настройка порога неактивности и правил учёта Idle.
- Автозапуск с Windows.
- Установщик и подпись кода.

## 3. Пользователь

Один пользователь Windows на одном компьютере. Данные хранятся локально, у каждой учётной записи Windows свой Timer и свой Timer Log.

## 4. Модель состояний

Каждый запуск приложения начинается в Stop.

| Из | В | Триггер |
|---|---|---|
| Stop | Active | кнопка «Старт» |
| Active | Stop | кнопка «Стоп» или выход из приложения |
| Idle | Stop | кнопка «Стоп» или выход из приложения |
| Active | Idle | нет ввода дольше Inactivity Threshold |
| Idle | Active | появился ввод |
| Active, Idle | Lock | блокировка, сон, гибернация, отключение RDP, смена пользователя |
| Lock | Active | компьютер разблокирован и не спит |
| Active, Idle, Lock | Shutdown | выключение компьютера, выход из учётной записи или Recovered Shutdown |
| Shutdown | Stop | новый запуск приложения |

Остальные пары состояний запрещены: такие события игнорируются и в Timer Log не пишутся. В частности, блокировка и выключение в Stop не создают Transition.

### Idle

- Inactivity Threshold равен 15 минутам и задан константой.
- Первые 15 минут без ввода входят в Counted Time. С момента перехода в Idle время не считается.
- Счётчик никогда не уменьшается автоматически.

### Lock

- Если компьютер проснулся, но экран заблокирован, Timer остаётся в Lock до разблокировки.
- В Timer Log указывается причина: `lock`, `sleep`, `remote-disconnect` или `user-switch`.

### Shutdown

- Штатное завершение записывается, когда оно окончательно. Запрос на завершение, который другое приложение может отменить, состояние не меняет.
- Выход из учётной записи обрабатывается так же, с причиной `logoff`.
- Приложение не задерживает завершение Windows. Закрытие окна при завершении не сворачивает приложение в трей.
- Пока Timer не в Stop, приложение раз в 30 секунд сохраняет отметку о том, что оно работает.
- Если при запуске последнее состояние в Timer Log не Stop и не Shutdown, добавляется Recovered Shutdown на время последней отметки. Запись помечается как восстановленная, затем Timer находится в Stop.
- При аварийном завершении теряется не больше 30 секунд Counted Time.

## 5. Учёт времени

- Daily Session — это Counted Time и Adjustment за локальный календарный день.
- Несколько запусков, остановок и перезагрузок за день не обнуляют Daily Session.
- Если Timer работает в полночь, время делится между двумя днями, Timer не останавливается, а счётчик новой Daily Session начинается с нуля.

### Adjustment

- Применяется только к текущей Daily Session и доступен в любом Timer State.
- Итог Daily Session должен оставаться в пределах от 0 до 24 часов. Значение вне этих границ отклоняется с понятной ошибкой и не обрезается.
- Комментарий необязателен.

## 6. Timer Log

- Единая хронология Transition и Adjustment. Записи только добавляются, их нельзя редактировать или удалять.
- Запись о Transition содержит время, старое и новое состояния и причину.
- Запись об Adjustment содержит время, количество минут и необязательный комментарий.
- Каждая запись также содержит уникальный ID, версию схемы и время в UTC со смещением часового пояса.
- Экран лога по умолчанию показывает текущий день и позволяет выбрать другую дату.
- Записи хранятся бессрочно.

## 7. Интерфейс

- Окно показывает Timer State и длительность текущей Daily Session.
- В окне есть кнопки «Старт» и «Стоп», ввод Adjustment и экран Timer Log.
- Приложение работает с иконкой в трее. Закрытие окна сворачивает его в трей, а завершает работу пункт «Выход» в меню трея.
- Допускается один экземпляр приложения. Повторный запуск открывает окно работающего экземпляра.

## 8. Техническое решение

- .NET 10 и WinForms.
- Домен находится в отдельной библиотеке без зависимостей от Windows. Для других ОС заменяются UI и адаптеры ОС.
- Неактивность определяется опросом `GetLastInputInfo` раз в 5–10 секунд. Глобальные хуки и Raw Input не используются, поскольку они похожи на поведение кейлоггера и настораживают антивирусы.
- Хранение: append-only JSONL в `%LOCALAPPDATA%`, итог дня вычисляется из Timer Log. См. [ADR-0001](adr/0001-append-only-log-as-source-of-truth.md).
- Поставка: zip-архив с self-contained сборкой, без упаковки в один файл и без обфускации.

## 9. Принятые ограничения

- Просмотр видео без ввода считается неактивностью.
- Программы, имитирующие движение мыши, считаются активностью.
- Ручной перевод системных часов искажает учёт. Отрицательный интервал считается нулём, а ошибку можно исправить через Adjustment.
- Без подписи кода SmartScreen может показать предупреждение при первом запуске. Это нужно описать в README.
- Локальный файл можно отредактировать вручную, поэтому Timer Log не подходит как доказательство для расчётов с сотрудниками.
