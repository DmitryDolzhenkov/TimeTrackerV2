# Start and stop the Timer with a persisted Daily Session

Blocked by: —

PRD: разделы 3, 4, 5, 6, 8. ADR: 0001.

## Что делаем

Первый сквозной срез. Пользователь запускает и останавливает Timer и видит Daily Session, которая переживает перезапуск приложения.

Тикет также создаёт основу решения: библиотеку домена без зависимостей от Windows, приложение WinForms на .NET 10, тестовый проект и `.gitignore`.

## Критерии приёмки

- [ ] Решение собирается на .NET 10. Проект домена не использует Windows-специфичные API и WinForms.
- [ ] Новый запуск приложения начинается в Stop.
- [ ] Кнопка «Старт» переводит Stop → Active, кнопка «Стоп» переводит Active → Stop.
- [ ] Окно показывает Timer State и длительность Daily Session, значение обновляется, пока Timer в Active.
- [ ] Повторный «Старт» в Active и «Стоп» в Stop не создают Transition и записи в Timer Log.
- [ ] Каждая Transition дописывается в JSONL-файл в `%LOCALAPPDATA%` со старым и новым состояниями, причиной, уникальным ID, версией схемы и временем в UTC со смещением.
- [ ] Daily Session вычисляется из Timer Log: после перезапуска приложения в тот же день показывается прежнее значение.
- [ ] Оборванная последняя строка файла пропускается и не мешает запуску и дальнейшей записи.
- [ ] Отрицательный интервал между записями считается нулём.
- [ ] Логика домена покрыта тестами с управляемым временем, чтение и запись файла покрыты тестами на временном файле.

## Вне тикета

Трей, полночь, Adjustment, экран лога, Idle, Lock и Shutdown.
